## 2. Treatment catalog

Support figures are from [caniuse data](https://github.com/Fyrd/caniuse) unless noted. Universal a11y rule: gate motion with `prefers-reduced-motion` ([MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion), Baseline widely available; [caniuse 97.2%](https://caniuse.com/prefers-reduced-motion)) and replace rather than remove ([Comeau](https://www.joshwcomeau.com/react/prefers-reduced-motion/)).

1. **Scroll-driven animations** (reveals, progress bars, pinned sequences via `animation-timeline: scroll()/view()`). Seen: Comeau writes on it ([site](https://www.joshwcomeau.com/)). Support: Chrome/Edge 115, Safari 26 ([Chrome docs](https://developer.chrome.com/docs/css-ui/scroll-driven-animations)); MDN still marks [animation-timeline](https://developer.mozilla.org/en-US/docs/Web/CSS/animation-timeline) "limited availability", so treat as progressive enhancement behind `@supports`. Cost: runs off the main thread; animate `transform`/`opacity` only. A11y: wrap in `no-preference`; content must read fine without it.
2. **View Transitions** (page-to-page morphs, shared hero image). No showcase site verified using it. Support: same-document Chrome/Edge 111, Safari 18, Firefox 144; cross-document Chrome/Edge 126, Safari 18.2, no Firefox ([Chrome docs](https://developer.chrome.com/docs/web-platform/view-transitions); [caniuse 92.9%](https://caniuse.com/view-transitions)). Cost: one snapshot per named element, so name few ([MDN](https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API)). A11y: shorten durations to ~0 under `reduce`; the API avoids duplicate-DOM focus and live-region problems that hand-built transitions cause.
3. **Layered, colour-matched shadows for depth.** Seen: Comeau's [shadow guide](https://www.joshwcomeau.com/css/designing-shadows/). Support: universal. Cost: each layer adds paint work, "5x more work"; don't animate shadows, fade a pseudo-element's opacity instead ([web.dev](https://web.dev/articles/animations-guide)). A11y: shadows can't carry meaning; keep text contrast.
4. **Layered parallax with CSS 3D transforms** (`perspective` + `translateZ`, no scroll handlers). Seen: GSAP-driven sites such as [Jesper Landberg](https://www.awwwards.com/sites/jesper-landberg-4); the pure-CSS route is from [Chrome's guide](https://developer.chrome.com/blog/performant-parallaxing). Cost: avoid scroll listeners and `background-position`; known Safari and Firefox sticky quirks. A11y: parallax is a classic vestibular trigger, so flatten fully under `reduce`.
5. **SVG line drawing and morphing** (`stroke-dashoffset`). Seen: Comeau's SVG micro-interactions ([site](https://www.joshwcomeau.com/)). How: [CSS-Tricks](https://css-tricks.com/svg-line-animation-works/); use `pathLength` to normalize. Cost: tiny for a few paths, expensive for hundreds of nodes. A11y: give the SVG `role="img"` with a title, or `aria-hidden` if decorative; show the finished drawing under `reduce`.
6. **Canvas/WebGL accents** (one hero scene, not a whole site). Seen: [Bruno Simon](https://www.awwwards.com/sites/brunos-portfolio), [Lando Norris](https://www.awwwards.com/sites/lando-norris), [Heckel](https://blog.maximeheckel.com/). Support: [WebGL2 97.1%](https://caniuse.com/webgl2), [OffscreenCanvas 96.3%](https://caniuse.com/offscreencanvas). Cost: highest of all; dynamic-`import()` the 3D code after first paint, render in a worker via [OffscreenCanvas](https://developer.mozilla.org/en-US/docs/Web/API/OffscreenCanvas), pause when off-screen, cap pixel ratio. A11y: Bruno's A11y jury scores are 6.6–7.0; keep an HTML text equivalent, a pause control, a static poster under `reduce`.
7. **Container queries** (art-direct a figure or card by its own width). Seen: Fisher's responsive experiments, where she says she wants container queries ([web.dev](https://web.dev/community-highlight-lynn-fisher/)). Support: [95.8%](https://caniuse.com/css-container-queries), Chrome 105, Firefox 110, Safari 16 ([MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_containment/Container_queries)). Cost: small; `container-type: inline-size` applies containment. A11y: don't shrink text below readable; cqi units follow the container, not user zoom, so keep a `rem` floor.
8. **Variable fonts with fallback matching** (expressive weight/width, one file). No showcase site verified. Support: [97.2%](https://caniuse.com/variable-fonts). Cost: one file beats many weights only if you use many styles; use WOFF2, subset with `unicode-range`, preload only the key face, tune the fallback with `size-adjust` to protect CLS ([web.dev](https://web.dev/articles/font-best-practices); [font-display 97.2%](https://caniuse.com/css-font-rendering-controls)). A11y: honor user zoom and `rem` units; avoid ultra-thin weights for body copy.
9. **Spring and bounce easing with `linear()`** (playful hover and entry motion, no JS). Seen: Comeau ([site](https://www.joshwcomeau.com/)). Support: Baseline widely available since Dec 2023 ([MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/easing-function/linear)). Cost: compositor-friendly when applied to `transform`. A11y: apply only inside `no-preference`.
10. **`@starting-style` entry animations** (fade/slide in popovers, dialogs, inserted nodes). Seen: Comeau covers it ([site](https://www.joshwcomeau.com/)). Support: Baseline 2024, newly available ([MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/@starting-style)). Cost: negligible. A11y: native `<dialog>`/popover keep focus handling; add the reduced-motion override.
11. **Scrollytelling with IntersectionObserver** (sticky chart that changes per paragraph). Seen: [The Pudding](https://pudding.cool/) via [Scrollama](https://github.com/russellgoldenberg/scrollama). Cost: observers avoid scroll-event jank; keep the sticky layer a single compositor layer. A11y: write the prose as real headings and paragraphs so the story is complete without the graphic; provide text alternatives for charts; use `position: sticky`, not hijacked scroll.
12. **Image and loading strategy** (the LCP guard for every treatment above). Preload or inline the hero in HTML, use `fetchpriority="high"` on it, never lazy-load it, and lazy-load everything else ([web.dev LCP](https://web.dev/articles/optimize-lcp); [lazy loading 96.4%](https://caniuse.com/loading-lazy-attr)). Add `width`/`height` to prevent CLS. Use [`content-visibility: auto`](https://caniuse.com/css-content-visibility) (94.9%) for long essays. A11y: meaningful `alt`; empty `alt` for decoration.
13. **Per-essay interactive widgets, code-split.** Seen: Comeau builds a custom widget for nearly every post ([summary](https://yespress.io/josh-w-comeau)). Cost: load each widget's JS only on its page, ideally on visibility, via [dynamic `import()`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/import); keep handlers short for INP ≤ 200 ms ([web.dev](https://web.dev/articles/inp)). A11y: real buttons and inputs, visible focus, keyboard operable.

## Suggested stance

Use plain semantic HTML as the base, one signature moment per essay (WebGL or scroll-driven), and CSS-only polish elsewhere (shadows, `linear()`, `@starting-style`). Then measure your own pages in the field, since I could not measure the sites above.
